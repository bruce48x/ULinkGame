# Remote Actor Messaging — AskRemoteAsync & TellRemoteAsync

Location-aware remote actor messaging lets you call an actor that lives on a different node. The API explicitly marks the call as remote to preserve visibility of network boundaries.

## API

```csharp
// Request-reply: send a message, wait for a response
var result = await runtime.AskRemoteAsync<TResult>(
    router,              // IClusterRouter
    gateway,             // RemoteActorGateway
    routeDirectory,      // IRouteDirectory
    localNode,           // NodeId of this node
    "player/alice",      // target actor ID
    "login",             // message kind
    () => Serialize(request),        // serialize payload
    payload => Deserialize<TResult>(payload),  // deserialize response
    TimeSpan.FromSeconds(5),
    cancellationToken);

// Fire-and-forget: send a message, don't wait
await runtime.TellRemoteAsync(
    router, localNode,
    "player/alice", "notify",
    () => Serialize(notification),
    TimeSpan.FromSeconds(5),
    cancellationToken);
```

## How it works

```
Sending node                         Receiving node
────────────                         ──────────────

AskRemoteAsync:
  1. Registers reply route
     ("actor-reply:<localNode>")
  2. Creates ClusterActorEnvelope     3. ClusterActorDispatcher
     with ReplyCorrelationId ─────────→  dispatches to actor
  4. Registers pending TCS            5. Handler processes request
     in RemoteActorGateway            6. Handler calls SendReplyAsync
  7. Receives reply payload ←────────  if ReplyCorrelationId is set
     via reply handler
  8. Completes TCS
  9. Deserializes and returns result
```

## Reply convention

- Reply route: `"actor-reply:<nodeId>"` (generated by `ClusterActorRouteKeys.ForReply`)
- Reply message kind: `"_actor_reply"` (`RemoteActorGateway.ReplyKind`)
- Correlation: the reply's `CorrelationId` matches the request's `ReplyCorrelationId`

The replying handler calls `RemoteActorGateway.SendReplyAsync()` with the cluster router, source node, correlation ID, and serialized payload.

## Cluster handler composition

When a node receives a cluster message, it needs to distinguish reply messages from actor messages. Use `CompositeClusterMessageHandler`:

```csharp
var handler = new CompositeClusterMessageHandler(
    gateway.CreateReplyHandler(),          // handles "_actor_reply" kind
    new ClusterActorDispatcher<PlayerActor>(...),  // handles actor messages
    new ClusterActorDispatcher<RoomActor>(...)
);
```

Each handler returns `RouteNotFound` if the message isn't for it. The composite tries them in order and stops at the first non-`RouteNotFound` result.

## Serialization

The framework does not bundle a serializer. You provide `Func<ReadOnlyMemory<byte>>` for serialization and `Func<ReadOnlyMemory<byte>, TResult>` for deserialization. This keeps the cluster layer serializer-agnostic.

A wrapper can simplify the common case:

```csharp
public static async ValueTask<TResult> AskRemoteAsync<TRequest, TResult>(
    this IActorRuntime runtime,
    IClusterRouter router,
    RemoteActorGateway gateway,
    IRouteDirectory directory,
    NodeId localNode,
    string actorId,
    string kind,
    TRequest request,
    TimeSpan timeout,
    CancellationToken ct = default)
{
    var serializer = MemoryPackSerializer.Instance; // or your choice
    return await ActorRuntimeRemoteExtensions.AskRemoteAsync<TResult>(
        runtime, router, gateway, directory, localNode, actorId, kind,
        () => serializer.Serialize(request),
        payload => serializer.Deserialize<TResult>(payload),
        timeout, ct);
}
```

## RemoteActorGateway

`RemoteActorGateway` manages pending request state:

- `RegisterPendingAsync(correlationId, timeout, ct)` — returns a `Task<ReadOnlyMemory<byte>>` that completes when the reply arrives
- `CreateReplyHandler()` — returns an `IClusterMessageHandler` that matches reply messages and completes pending TCSs
- `SendReplyAsync(router, sourceNode, correlationId, payload, ct)` — static helper for handler code to send replies

## Naming

The `Remote` suffix is intentional. `AskAsync` is process-local (takes a lambda, runs in-process). `AskRemoteAsync` crosses the network (takes serializable payload, involves routing). The developer always knows which is which at the call site.
